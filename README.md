# depviz — граф зависимостей пакетов Ubuntu (вариант 14)

Практическая работа №2 по дисциплине «Конфигурационное управление».

## 1. Общее описание

depviz строит граф зависимостей пакета Ubuntu (apt) и выводит его как
список прямых зависимостей, полный граф, порядок загрузки или описание
на языке диаграмм [D2](https://d2lang.com).

Готовые менеджеры пакетов и библиотеки для получения зависимостей не
используются. Индекс репозитория (`Packages`, `Packages.gz`,
`Packages.xz`) скачивается по URL и разбирается вручную; сравнение
версий Debian реализовано самостоятельно. Для проверки алгоритмов есть
тестовый режим: граф описывается в файле, пакеты названы большими
латинскими буквами.

| Этап | Что сделано | Модуль |
|---|---|---|
| 1 | параметры командной строки и их проверка | `cli.py` |
| 2 | загрузка индекса apt, прямые зависимости | `apt_index.py`, `debversion.py` |
| 3 | граф рекурсивным DFS, фильтр, циклы, тестовый режим | `graph.py`, `sources.py` |
| 4 | порядок загрузки, сравнение с apt-get | `order.py`, `scripts/compare_with_apt.sh` |
| 5 | описание графа на D2, сравнение с apt-cache dotty | `d2.py` |

Структура репозитория:

```
src/depviz/          исходный код
  __main__.py        точка входа, выбор режима
  cli.py             параметры командной строки
  apt_index.py       загрузка и разбор индекса Packages
  debversion.py      сравнение версий Debian
  sources.py         источники зависимостей: apt и тестовый файл
  graph.py           граф зависимостей (рекурсивный DFS)
  order.py           порядок загрузки
  d2.py              описание графа на языке D2
tests/               модульные тесты (unittest)
tests/fixtures/      реальные данные Ubuntu 24.04 и тестовые графы
docs/examples/       примеры D2 и вывод apt-cache dotty
scripts/             скрипт сравнения с apt-get
```

## 2. Функции и настройки

### Параметры командной строки

| Параметр | Описание |
|---|---|
| `--package NAME` | имя анализируемого пакета (обязательный) |
| `--repo URL\|PATH` | URL индекса `Packages` или путь к файлу тестового репозитория (обязательный) |
| `--test-mode` | режим работы с тестовым репозиторием |
| `--version VER` | версия пакета; без неё берётся самая новая |
| `--filter SUBSTR` | не учитывать пакеты, имя которых содержит подстроку |
| `--mode MODE` | что выводить: `deps`, `graph` (по умолчанию), `order`, `d2` |
| `--output FILE` | сохранить описание D2 в файл (только с `--mode d2`) |

Режимы `--mode`: `deps` — прямые зависимости, `graph` — граф с учётом
транзитивности, `order` — порядок загрузки, `d2` — описание на D2.

Проверки: формат имени пакета (строчные буквы, цифры, `+ . -`; в
тестовом режиме — большие латинские буквы), схема и сервер URL
(`http`, `https`, `file`), существование тестового файла, формат версии
Debian (в тестовом режиме версия не допускается), непустой фильтр без
пробелов, папка для `--output`. Ошибка параметров — код возврата 2,
ошибка данных (сеть, нет пакета или версии, формат файла) — код 1.

### Индекс репозитория (этап 2)

`--repo` — URL файла индекса, например
`http://archive.ubuntu.com/ubuntu/dists/noble/main/binary-amd64/Packages.gz`.
Сжатие gzip и xz определяется по сигнатуре.

- Индекс — блоки «поле: значение» через пустую строку (RFC 822);
  строки, начинающиеся с пробела, продолжают значение.
- Зависимости берутся из `Pre-Depends` и `Depends`: группы через
  запятую, альтернативы `a | b`, ограничения версий в скобках,
  квалификаторы `:any` и `[arch]` отбрасываются.
- Из группы альтернатив берётся первая, которая есть в индексе; если
  это виртуальный пакет, — первый пакет, который его предоставляет
  (`Provides`). Так поступает apt по умолчанию.
- Без `--version` выбирается самая новая версия по правилам Debian
  (эпоха, основная часть, ревизия, `~`). Алгоритм проверен против
  `dpkg --compare-versions` на 596 парах версий.

### Граф (этап 3)

Граф строится рекурсивным обходом в глубину. Пакет на текущем пути
обхода помечается «серым», полностью обработанный — «чёрным». Ребро в
серый пакет — цикл: он записывается, а обход по нему не продолжается.
Пакеты с подстрокой `--filter` в имени не попадают в граф и не
обходятся. Пакеты, которых нет в репозитории, остаются листьями с
пометкой `(нет в репозитории)`.

Файл тестового репозитория — по пакету на строку `A: B C`; пустые строки
и строки, начинающиеся с решётки, пропускаются. Примеры — в
`tests/fixtures/graphs/`:

| Файл | Случай |
|---|---|
| `chain.txt` | цепочка A → B → C → D |
| `diamond.txt` | общая зависимость (ромб) |
| `cycle.txt` | цикл A → B → C → A |
| `self_loop.txt` | пакет зависит сам от себя |
| `missing.txt` | зависимость не описана в репозитории |
| `complex.txt` | два цикла и общие зависимости, удобно для `--filter` |
| `broken.txt` | ошибка формата |

### Порядок загрузки (этап 4)

Обратный обход в глубину (post-order): пакет идёт после всех своих
зависимостей, корневой пакет последний. В цикле ребро в пакет, который
сейчас в стеке обхода, пропускается, а разрыв выводится строкой
`Цикл разорван: ...`.

`scripts/compare_with_apt.sh ПАКЕТ [URL_Packages]` собирает из индекса
локальный репозиторий, моделирует `apt-get install -s
--no-install-recommends` на «чистой» системе (пустой dpkg status) и
сравнивает порядок строк `Conf` с depviz. Нужен Ubuntu/Debian или WSL.

Результаты на данных Ubuntu 24.04 (1021 пакет из dpkg status):

| Пакет | apt-get | depviz | Порядок |
|---|---|---|---|
| `tar` | 7 | 7 | совпадает полностью |
| `coreutils` | 10 | 10 | совпадает полностью |
| `apt` | 35 | 35 | совпадает полностью |
| `bash` | 9 | 9 | те же пакеты, 4 позиции иначе |

```
apt-get        depviz
gcc-14-base    gcc-14-base
libgcc-s1      libgcc-s1
libc6          libc6
libcrypt1      libtinfo6     <-
mawk           mawk
base-files     libcrypt1     <-
libtinfo6      base-files    <-
debianutils    debianutils
bash           bash
```

Почему возможны расхождения:

- **Приоритет Essential.** `base-files` помечен `Essential: yes`, и apt
  настраивает его (вместе с `libcrypt1` и `mawk`) раньше обычных
  пакетов. depviz обходит зависимости в порядке записи в индексе
  (сначала `Pre-Depends` bash: `libc6`, `libtinfo6`). Оба порядка
  корректны: каждая зависимость идёт раньше зависящего от неё пакета.
- **Распаковка и настройка.** apt разделяет `Inst` (распаковка) и `Conf`
  (настройка). В цикле `libc6 <-> libgcc-s1` apt распаковывает оба
  пакета, а настраивает сначала `libgcc-s1`; порядок depviz совпадает
  с порядком `Conf`.
- **Рекомендации.** По умолчанию apt ставит и `Recommends`; depviz их не
  учитывает, поэтому сравнение идёт с `--no-install-recommends`.
- **Установленные пакеты.** На настоящей системе apt пропускает уже
  установленные пакеты, depviz строит полный порядок с нуля.
- **Версии и альтернативы.** apt проверяет ограничения версий и может
  выбрать уже установленную альтернативу или поставщика виртуального
  пакета; depviz берёт первую существующую альтернативу и самую новую
  версию.

### Описание на D2 (этап 5)

`--mode d2` выводит граф на языке D2, `--output FILE` дополнительно
сохраняет его в файл. Имена пакетов взяты в кавычки (точка в D2 —
вложенность фигур). Корневой пакет выделен заливкой, отсутствующие
пакеты — пунктирной рамкой, ребро, замыкающее цикл, — красным пунктиром
с подписью «цикл».

Картинку можно получить утилитой D2 (`d2 tar.d2 tar.svg`) или вставив
текст на [play.d2lang.com](https://play.d2lang.com).

Примеры для трёх пакетов лежат в `docs/examples/`: `tar.d2`,
`bash.d2`, `coreutils.d2`, рядом — вывод штатного инструмента
`apt-cache dotty` для тех же пакетов (`*.apt-cache-dotty.dot`).

Сравнение с `apt-cache dotty` на тех же данных Ubuntu 24.04:

| Пакет | Рёбра зависимостей dotty | Рёбра depviz | Рёбра Conflicts/Breaks в dotty |
|---|---|---|---|
| `tar` | 10 | 10, совпадают | 20 |
| `coreutils` | 16 | 16, совпадают | 21 |
| `bash` | 13 | 14 | 27 |

Почему результаты различаются:

- **Конфликты.** dotty рисует зелёным и рёбра `Conflicts`/`Breaks` —
  к пакетам вроде `firefox` или `valgrind`, которые не нужны для
  установки. depviz показывает только то, что нужно установить.
- **Виртуальные пакеты.** У `bash` через `base-files` есть зависимость
  от виртуального `awk`. dotty останавливается на нём (треугольник),
  depviz подставляет реальный `mawk` и продолжает обход
  (`mawk -> libc6`), поэтому у depviz на одно ребро больше.
- **Альтернативы.** dotty показывает все альтернативы группы `a | b`,
  depviz — только выбранную.
- **Оформление.** В dotty форма вершины обозначает тип пакета (обычный,
  виртуальный, отсутствующий), цвет ребра — вид связи (`Pre-Depends`
  синим). В depviz выделены корень, отсутствующие пакеты и циклы.

## 3. Сборка и запуск тестов

Требуется Python 3.10+. Сторонние пакеты не нужны (`requirements.txt`
пустой), сборка не требуется.

```sh
pip install -r requirements.txt    # зависимости
./run.sh [параметры]                # Linux / macOS
run.bat [параметры]                 # Windows
make test                           # модульные тесты
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

В Windows (PowerShell) тесты: `$env:PYTHONPATH="src"`, затем
`python -m unittest discover -s tests -v`.

```sh

./run.sh --package tar --repo $REPO --mode graph --filter selinux
./run.sh --package apt --repo $REPO --mode order
```
